# CKS Knowledge Runtime — этап 3: Obsidian

## Цель

Сделать CKS удобным для визуального исследования в Obsidian прямо из Git-папки, не превращая Obsidian в источник истины и не создавая второй рабочий контур знаний.

## Что уже существовало до этапа

В `tools/cks_knowledge_runtime.py` уже были:

- нормализация объектов знаний;
- индексы кластеров, тегов, статусов и проектов;
- динамические представления;
- базовый Markdown-экспорт для Obsidian;
- wiki-ссылки на связанные объекты и доказательства.

Поэтому новый Knowledge Runtime не создавался.

## Реализовано

### 1. Расширенный Obsidian-экспорт

Добавлен `tools/cks_obsidian_export.py`.

Он использует существующий `KnowledgeRuntime` и формирует производную структуру Vault:

```text
CKS_Обзор.md
OBSIDIAN_CKS_README.md
Знания/
Кластеры/
Теги/
Проекты/
Статусы/
Карты/
  CKS_Граф.canvas
```

### 2. Навигационные представления

Для каждого объекта формируются ссылки на:

- кластеры;
- теги;
- проекты-проекции;
- статус развития знания.

Для каждого кластера, тега, проекта и статуса создаётся индексная заметка со ссылками на входящие объекты.

### 3. Canvas — графическое представление

Создаётся `Карты/CKS_Граф.canvas`.

Узлы Canvas ссылаются на реальные Markdown-заметки объектов CKS. Координаты узлов распределяются по стадиям движения знания: от входного материала к знанию, канону и истории.

Рёбра Canvas строятся только из существующих связей и ссылок на доказательства. Canvas не добавляет новые факты в CKS.

### 4. Русский режим

Навигация, названия представлений, пояснения и документация формируются на русском языке. Английские технические идентификаторы сохраняются только там, где это нужно машинному контракту или совместимости.

### 5. Автоматические тесты

Добавлен `tests/test_cks_obsidian_stage3.py`.

Тесты проверяют:

- создание структуры Obsidian Vault;
- Markdown-заметки объектов;
- wiki-ссылки;
- русскую навигацию;
- индексы кластеров, тегов, проектов и статусов;
- наличие Canvas;
- узлы и рёбра Canvas;
- явную маркировку Obsidian как производного представления, а не SSOT.

## Контроль предыдущих ошибок

1. Не создан второй объектный Runtime.
2. Obsidian не объявлен SSOT.
3. Canvas не объявлен Canon или источником данных.
4. Наличие тестов не объявлено доказательством их успешного выполнения.
5. Projects (проекты) остаются проекциями графа, а не контейнерами файлов.
6. Документация и пользовательские представления ведутся по-русски.

## Что сознательно отложено

Этап 3 не реализует полный динамический экран «мусор → знания» и аналитические виды по конфликтам, связности и времени. Это следующий этап 4.

Также фактический прогон тестов GitHub Actions будет подтверждаться на этапе 7.
