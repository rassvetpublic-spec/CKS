# CKS 1.2 Архитектурные решения

## Назначение документа

Документ фиксирует предварительные архитектурные решения для этапа CKS 1.2.

Важно: CKS 1.2 пока является этапом анализа и проектирования. Реализация не начинается до отдельного решения.

---

# 1. Сохраняем ядро CKS

Решение:

CKS 1.2 не изменяет фундамент:

```
Knowledge Object
        ↓
Reference
        ↓
Decision
        ↓
Evidence
```

Ядро остаётся простым и независимым.

---

# 2. Context Passport

Статус:

```
ANALYSIS
```

Назначение:

- описывать происхождение внешнего контекста;
- сохранять связь с источником;
- обеспечивать проверяемость импорта.

Решение:

Не является новым типом хранилища.

---

# 3. Worker Manifest

Статус:

```
ANALYSIS
```

Назначение:

- описывать возможности внешних исполнителей;
- ограничивать операции.

Ограничение:

Worker Manifest не превращает CKS в исполнительную систему.

---

# 4. External Adapter Contract

Статус:

```
ANALYSIS
```

Назначение:

Безопасный обмен проверенными артефактами.

Принцип:

```
External System
      ↓
Validated Artifact
      ↓
CKS Object
```

---

# 5. Import Pipeline

Статус:

```
ANALYSIS
```

Предварительная модель:

```
External Package
        ↓
Validation
        ↓
Candidate Object
        ↓
CKS Lifecycle
```

---

# 6. Advanced Validation

Статус:

```
ANALYSIS
```

Причина:

Нельзя добавлять сложность проверки без реальных сценариев использования.

---

# 7. Promotion Workflow

Статус:

```
ANALYSIS
```

Принцип:

Автоматическое продвижение знаний не является целью CKS 1.2 по умолчанию.

---

# Архитектурные запреты

Запрещено:

- хранить runtime состояние;
- хранить память агентов;
- зависеть от KAT9I_OS;
- превращать CKS в систему исполнения;
- импортировать необработанный контекст.

---

# Итоговое решение

CKS 1.2 должен развивать безопасное взаимодействие с внешними системами, но не менять роль CKS:

```
CKS = источник знаний

Внешние системы = пользователи и поставщики артефактов
```
