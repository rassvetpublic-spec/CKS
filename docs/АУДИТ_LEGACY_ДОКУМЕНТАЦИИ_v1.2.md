# Аудит Legacy документации CKS v1.2

## Цель

Проверка документации после изоляции Legacy (наследия) и отделение исторических материалов от действующего состояния CKS v1.2.

## Правила

- Core (ядро системы) не изменяется материалами из Legacy.
- Исторический документ не является решением.
- Эксперимент не становится каноном автоматически.
- Предложение не становится решением без процедуры принятия.

## Проверенные зоны

| Зона | Статус |
|---|---|
| docs | требуется классификация по статусу |
| ADR | решения должны иметь явный статус |
| Architecture | относится к контролируемой документации |
| Audit reports | исторические отчёты не являются Core |

## Решение

Документы сохраняются до завершения полной классификации. Удаление не выполняется без доказательства отсутствия ценности.

## Процесс возврата материала

GAP (разрыв)

→ Evidence (доказательство)

→ Proposal (предложение)

→ Decision (решение)

→ Minimal Change (минимальное изменение)
