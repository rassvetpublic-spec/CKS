# CKS — поэтапный план Knowledge Runtime и Knowledge Intelligence

Статус: рабочий план развития, не Canon.

Язык документации: русский. Английские технические термины допускаются только с русским пояснением.

## Зачем этот план

Работа разбита на небольшие этапы, чтобы не смешивать проектирование, реализацию, миграцию и аудит в одном проходе.

Главное правило развития CKS сохраняется:

GAP (разрыв) → Evidence (доказательство) → Proposal (предложение) → Decision (решение) → Minimal Change (минимальное изменение).

## Этап 1 — сверка существующей модели и запрет дублей

Цель: понять, что уже реализовано, и не создавать повторные схемы и несовместимые сущности.

Проверить и связать:
- единую схему объекта знания;
- кластеры и теги;
- статусы развития знания;
- динамические представления;
- параметры Obsidian;
- русскоязычные правила документации.

Результат: карта «уже есть / отсутствует / конфликтует / требует реализации».

## Этап 2 — Knowledge Runtime (рабочая модель знаний)

Цель: превратить описания в исполняемый слой.

Работы:
1. проверка объектов по единой схеме;
2. нормализация кластеров и тегов;
3. формальные переходы статусов;
4. Graph Object Lifecycle (жизненный цикл объектов графа);
5. Node Versioning (версии узлов);
6. Relation History (история связей).

Результат: объект знания можно создать, проверить, изменить и проследить его историю без потери происхождения.

## Этап 3 — Obsidian и представления

Цель: использовать Git-папку CKS как совместимое хранилище для визуального исследования в Obsidian.

Работы:
1. Markdown-представление объекта;
2. YAML frontmatter (метаданные в начале Markdown-файла);
3. Wiki-ссылки `[[...]]`;
4. теги и алиасы;
5. совместимость с Graph View (графом Obsidian);
6. генерация производных заметок без изменения SSOT.

Результат: Obsidian является графическим представлением базы, но не источником истины.

## Этап 4 — динамические представления и «мусор → знания»

Цель: показывать процесс превращения входного материала в структурированное знание.

Представления:
- по статусам;
- по типам;
- по кластерам;
- по тегам;
- по времени;
- по уверенности;
- по проектам;
- по конфликтам;
- по происхождению;
- по степени связности.

Отдельное представление:

сырой материал → захвачено → нормализовано → сгруппировано → понято → связано → знание → канонический элемент.

Результат: Projects (проекты) становятся динамическими проекциями графа знаний, а не папками файлов.

## Этап 5 — Knowledge Intelligence I (поиск структуры)

Цель: обнаруживать структуру, которая не была задана вручную.

Работы:
1. поиск скрытых связей;
2. кандидаты новых кластеров;
3. поиск изолированных и слабосвязанных узлов;
4. обнаружение конфликтующих знаний;
5. оценка уверенности и новизны.

Все результаты являются предложениями или сигналами, а не решениями.

## Этап 6 — Knowledge Intelligence II (эволюция знания)

Цель: анализировать, как материал стал знанием.

Работы:
1. анализ «что стало знанием»;
2. карта развития проекта;
3. история узлов и связей;
4. Graph Migration Engine (движок миграции графа);
5. Graph Recovery System (система восстановления графа).

Результат: можно восстановить путь от сырого входа до текущей структуры знаний и откатить ошибочную трансформацию.

## Этап 7 — самоаудит и интеграция

Цель: связать Runtime, Intelligence, Governance CI и Self Audit.

Работы:
1. самоаудит качества знаний;
2. проверка схем;
3. проверка происхождения;
4. проверка графа;
5. проверка русскоязычного режима документации;
6. негативные тесты;
7. миграционный аудит старых объектов;
8. итоговый отчёт без автоматического изменения Canon.

## Постоянные ограничения

- Graph (граф) ≠ SSOT (источник истины).
- Представление ≠ Canon (канон).
- Метрика ≠ решение.
- Интуиция ≠ доказательство.
- Автоматизация ≠ утверждение.
- Obsidian ≠ источник истины.
- Project (проект) = представление графа, а не контейнер файлов.

## Порядок выполнения

Выполнять строго по одному этапу за проход. После каждого этапа:
1. проверять фактические файлы GitHub;
2. искать регрессии и дубли;
3. фиксировать остаточные задачи;
4. только после этого переходить к следующему этапу.
