# CKS HANDSOFF GitHub Result Contract

## Назначение

HANDSOFF должен не только выполнять проверку, но и оставлять проверяемый след результата.

## Принцип

```
HANDSOFF
  ↓
проверки окружения
  ↓
проверка CKS
  ↓
SSOT discovery
  ↓
RESULT
  ↓
GitHub history
```

## Требования

1. Запуск из любой рабочей папки.
2. Поиск CKS через локальный путь или fallback clone.
3. Проверка identity репозитория.
4. Проверка основных якорей.
5. Формирование итогового статуса:

- READY
- BLOCKED
- UNKNOWN

6. Результат должен быть связан с GitHub commit history, а не только с выводом терминала.

## Расширения

- Repair mode — исправление локального состояния.
- E4.5 check — отдельная проверка доказательств.
- Result artifact — отдельный сохраняемый отчёт.

## Запрещено

- скрытые проверки без вывода;
- временные clone без очистки;
- зависимость от конкретного локального пути.
