# CKS Controller Protocol v1

## Назначение

Контроллер CKS — слой проверки жизненного цикла задач.

Он не выполняет работу и не принимает архитектурные решения.

Его задача — проверить, что процесс соблюдает установленные протоколы.

## Граница ответственности

CKS Controller:

- проверяет наличие обязательных элементов;
- проверяет последовательность процесса;
- фиксирует блокировки;
- передаёт управление следующему этапу.

CKS Controller НЕ:

- пишет код;
- заменяет Worker;
- заменяет QA;
- заменяет Review;
- изменяет Canon самостоятельно.

## Цикл проверки

Issue

↓

Контракт задачи (Task Contract)

↓

Передача задачи (HANDOFF)

↓

Worker

↓

Запрос проверки качества (QA)

↓

Архитектурная проверка (Review)

↓

Доказательства (Evidence)

↓

Разрешение слияния (Merge Gate)

## Проверки

Обязательно:

- есть идентификатор задачи;
- есть версия задачи;
- есть канал обратной связи;
- есть формат отчёта;
- есть доказательства результата;
- отсутствует самопроверка исполнителем.

## Статусы

PENDING — ожидает

RUNNING — выполняется

BLOCKED — заблокировано

READY — готово

DONE — завершено

## Совместимость

CKS Controller работает только через контракт.

KAT9I_OS может использовать собственные исполнители, инструменты и процессы без изменения CKS.

## Метрики

Проверяем:

- покрытие протоколов;
- наличие доказательств;
- количество блокировок;
- соответствие границам CKS/KAT9I_OS.
