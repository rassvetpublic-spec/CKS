# CKS Handover

## Назначение

Единая точка восстановления контекста CKS после завершения рабочего чата.

Документ не является новым архитектурным решением. Он содержит навигацию по уже зафиксированным материалам.

---

# Текущее состояние

## CKS 1.1

Статус по зафиксированным материалам:

- архитектура: утверждена;
- Core: заморожен;
- выпуск: Stable;
- эксплуатационная проверка: завершена.

Основной принцип:

```
CKS = система знаний
KAT9I_OS = система исполнения
GitHub = история разработки
```

# Неизменяемые правила CKS 1.1

1. CKS хранит знания, а не процессы.
2. Lifecycle описывает состояние знания, а не выполнение задач.
3. Evidence подтверждает знание, но не заменяет архив.
4. Reference является ссылкой, а не копией.
5. Новые элементы Core требуют ADR.
6. CKS 1.2 начинается только от подтверждённого ограничения CKS 1.1.

# После открытия нового рабочего чата

Порядок:

1. Прочитать этот файл.
2. Прочитать Bootstrap Snapshot.
3. Проверить Open Items.
4. Проверить актуальное состояние GitHub.
5. Продолжать только с подтверждённых задач.
