# CKS Knowledge Runtime — этап 1: аудит существующей модели

Статус: аудит реализации. Документ не является Canon.

## Проверено фактически

В репозитории уже существует `schemas/cks-knowledge-object.schema.json` — единая JSON Schema (схема данных) объекта знания.

Она уже содержит:
- `id`, `title/name`, `type`, `version`;
- подробные статусы развития знания;
- `owner` и `lifecycle`;
- `clusters` и `tags`;
- `projects` как проекции графа;
- `relations` с основанием, доказательствами, уверенностью и историей;
- `evidence`;
- `traceability` (происхождение знания);
- `history`;
- `signals`: уверенность, важность, новизна, неопределённость, интуиция;
- `obsidian`: aliases, cssclasses, folder, publish;
- `source`.

Также существует `schemas/cks-knowledge-view.schema.json` — схема динамического представления знаний. Она уже предусматривает виды:
- по статусам;
- по типам;
- по кластерам;
- по тегам;
- по проектам;
- по уверенности;
- путь «материал → знание».

## Главная коррекция предыдущей работы

Не создавать новую параллельную «единую схему объекта знания»: она уже существует.

Все следующие работы должны расширять или использовать существующие контракты после проверки совместимости, а не плодить новые конкурирующие схемы.

## Что уже закрыто моделью

### Knowledge Runtime

1. Единая схема объекта знания — есть.
2. Кластеры и теги — есть в схеме.
3. Богатая система статусов — есть в схеме.
4. Базовая связь с Obsidian — есть в схеме.
5. Контракт динамических представлений — есть отдельной схемой.

Это означает, что следующий этап должен быть реализационным, а не ещё одним описанием тех же полей.

## Что ещё не подтверждено как рабочая реализация

1. Валидатор объектов именно по текущей единой схеме.
2. Формальные допустимые переходы между статусами.
3. Нормализация кластеров и тегов и защита от синонимического мусора.
4. Генератор Markdown-заметок для Obsidian из объектов CKS.
5. Обратная безопасная синхронизация из Obsidian без превращения Obsidian в SSOT.
6. Исполняемый Node Versioning (версии узлов).
7. Исполняемая Relation History (история связей).
8. Рабочие динамические представления на реальных объектах.
9. Graph Migration Engine (движок миграции графа).
10. Graph Recovery System (система восстановления графа).

## Что ещё не реализовано на уровне Knowledge Intelligence

1. Поиск скрытых связей.
2. Выявление кандидатов новых кластеров.
3. Анализ перехода «сырой материал → знание» на истории реальных объектов.
4. Карта развития проекта как производная проекция графа.
5. Самоаудит качества знаний на реальном наборе объектов.

## Контроль старых ошибок

### Ошибка: проект как папка

Правило: Project (проект) — производное представление графа знаний, не контейнер файлов.

### Ошибка: английская документация

Правило: документация и человеческие названия — на русском. Технические идентификаторы могут оставаться английскими для совместимости.

### Ошибка: смешение модели и реализации

Наличие схемы или документа не означает наличие рабочего Runtime (исполняемого слоя).

### Ошибка: отчёт объявлялся завершением

Отчёт, дизайн и схема не считаются выполненной функцией без кода, теста и подтверждённого запуска там, где функция требует исполнения.

### Ошибка: новый файл вместо проверки существующего

Перед добавлением схемы, модели, workflow (сценария автоматизации) или runtime-модуля сначала проверять существующий репозиторий на функциональный дубль.

## Решение этапа 1

Этап 1 закрывает только инвентаризацию и устранение риска дублей.

Следующий этап: **Knowledge Runtime — этап 2: исполняемая модель знаний**.

Минимальный объём этапа 2:
- валидатор объекта по `schemas/cks-knowledge-object.schema.json`;
- таблица и проверка переходов статусов;
- нормализатор кластеров/тегов;
- тестовые положительные и отрицательные объекты.
