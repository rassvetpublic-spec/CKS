## Найденные незакрытые разрывы на входе в эту операцию

1. **История связей графа** — текущий рабочий граф хранит связи, доказательства и metadata, но отдельного полноценного механизма versioned Relation History пока не подтверждено.
2. **Миграция версии формата графа** — миграция объектов знаний существует, но отдельный Graph Migration Engine для схемы/формата самого графа пока не подтверждён.
3. **Восстановление графа** — граф умеет save/load и участвует в интегральной регрессии, но отдельный Graph Recovery System с журналом/снимками/проверкой целостности графового хранилища пока не подтверждён.
4. **Постоянное хранение итоговых CI-отчётов** — отчёты последнего самоаудита публикуются как временный GitHub Actions artifact; требуется постоянная запись итоговой сводки в репозиторий.
5. **Документационный дрейф версий** — корневые `README.md` и `ARCHITECTURE.md` по-прежнему описывают базовый frozen Core v1.2, тогда как `control/system-state.yaml` фиксирует current_version `CKS_v1.5` и развиваемый runtime. Это не должно исправляться простым переписыванием Canon: требуется явное различение baseline/Core и текущего рабочего слоя.

## Разбиение FULL KNOWLEDGE SNAPSHOT на короткие этапы

### Этап A — инвентаризация и сверка

- проверить все требования текущего чата против фактических файлов GitHub;
- разделить `реализовано / частично / отсутствует / только документировано`;
- не создавать функциональные дубли.

### Этап B — закрытие технических разрывов

- Relation History;
- Graph Migration Engine;
- Graph Recovery System;
- тесты этих функций;
- подключение к существующему CI.

### Этап C — постоянная фиксация состояния

- сохранить итог самоаудита и ключевые результаты CI не только во временном artifact;
- создать постоянный русский Snapshot текущего рабочего состояния;
- явно отразить различие frozen Core v1.2 и развиваемого рабочего слоя без самовольного повышения Canon.

### Этап D — финальная проверка сохранности чата

- повторная сверка требований чата с GitHub;
- поиск потерянных решений, долгов и ограничений;
- финальный CI;
- заключение `готов / не готов к удалению чата` с перечислением остающихся рисков.

## Текущая точка продолжения

**Следующий выполняемый шаг: Этап A.**  
После каждого этапа эта контрольная точка либо обновляется, либо дополняется отдельным отчётом, чтобы дисконнект окна не обнулял статус операции.
