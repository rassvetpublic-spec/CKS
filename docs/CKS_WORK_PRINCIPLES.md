# CKS Work Principles

## Укрупнение работы

### Принцип

Связанные изменения, направленные на одну архитектурную цель, выполняются как один укрупнённый пакет.

Не следует дробить единый результат на множество независимых микрозадач, если это увеличивает количество промежуточных подтверждений без добавления контроля.

## Модель работы

```
УКРУПНЁННЫЙ ПАКЕТ

исследование
+
проектирование
+
реализация
+
проверки
+
evidence (доказательства)
+
итоговый отчёт

↓

одно подтверждение завершения пакета
```

## Цель

Снизить:

- бюрократическую нагрузку;
- потерю контекста;
- повторный анализ;
- количество лишних остановок.

Сохранить:

- проверяемость;
- историю решений;
- доказательства изменений;
- контроль архитектурных рисков.

## Связь с Package Governance

Каждый укрупнённый пакет должен иметь:

- Package ID;
- цель;
- границы изменений;
- проверки;
- evidence;
- итоговый статус.

## Ограничение

Укрупнение не отменяет обязательные проверки для изменений высокого риска:

- Canon;
- SSOT;
- архитектурные границы;
- безопасность;
- необратимые решения.
