# ADR-007: Двуязычная модель документации CKS

## Статус

Принято.

## Контекст

CKS должен быть понятен человеку, ИИ и внешним системам. Полностью переводить технические идентификаторы нельзя, так как это создаёт проблемы совместимости с кодом, схемами, GitHub и интеграциями.

## Решение

CKS использует два языковых слоя.

## 1. Человеческий слой — русский язык

Используется для:

- архитектурных документов;
- описаний решений;
- правил;
- требований;
- задач;
- пользовательского взаимодействия.

Русский язык является основным языком описания архитектуры.

## 2. Технический слой — английский язык

Используется для:

- имён файлов при необходимости совместимости;
- программных идентификаторов;
- API;
- YAML/JSON полей;
- GitHub Actions;
- кода;
- внешних протоколов.

## Правило терминов

Каждый английский технический термин должен иметь:

1. английское имя;
2. простое русское объяснение;
3. место использования.

Единый источник терминологии:

`docs/ГЛОССАРИЙ.md`

## Запрещено

- механически переводить технические идентификаторы;
- использовать английские термины без определения;
- создавать смешанную терминологию без объяснения.

## Обоснование

Сохранение английских идентификаторов обеспечивает совместимость.
Русское описание сохраняет понятность архитектуры.

## Последствие

Все новые архитектурные документы CKS должны следовать языковой политике v1.0.
