# CKS Versioning Policy v1

## Purpose

Defines controlled evolution of CKS artifacts, protocols and schemas.

## Rules

- Breaking changes require a new major version.
- Schema changes require migration notes.
- Canonical decisions keep historical references.
- Deprecated objects are archived, not deleted.

## Version layers

- MAJOR: architecture or protocol incompatibility.
- MINOR: new capabilities without breaking compatibility.
- PATCH: corrections and clarifications.
