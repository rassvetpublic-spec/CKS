# CKS — рабочий контур и аналитика знаний

## Статус

Принятое развитие рабочего слоя CKS. Не изменяет замороженное ядро CKS v1.2 автоматически.

Связанное решение: `decisions/ADR-0002-knowledge-centric-runtime.md`.

## Главный принцип

CKS организует не файлы и не проекты как папки, а развитие знаний.

```text
сырой материал
      ↓
захват
      ↓
нормализация
      ↓
очистка дублей
      ↓
кластеры и теги
      ↓
исследование
      ↓
понимание
      ↓
связи
      ↓
проверка
      ↓
знание
      ↓
каноническая основа через Decision
```

Проект — это одна из проекций общего графа знаний.

# Часть I. CKS Knowledge Runtime (рабочий контур знаний)

## 1. Единая схема объекта знания

Основной машинный контракт: `schemas/cks-knowledge-object.schema.json`.

Ключевые группы полей:

- идентичность: `id`, `title`, `type`, `version`;
- состояние: `status`, `lifecycle`, `owner`;
- классификация: `clusters`, `tags`, `projects`;
- связи: `relations`, `evidence`, `traceability`;
- история: `history`;
- сигналы: `signals.confidence`, `importance`, `novelty`, `uncertainty`, `intuition`;
- отображение: `obsidian`.

Технические имена полей сохраняются на английском согласно ADR-007. Человеческие описания, статусы и представления выводятся на русском.

## 2. Кластеры и теги

Кластер — более устойчивое тематическое объединение объектов.

Тег — лёгкий признак, фасет или рабочая метка.

Один объект может одновременно принадлежать нескольким кластерам и иметь несколько тегов. Эти структуры используются для навигации и аналитики, но сами по себе не меняют авторитет знания.

## 3. Статусы развития знания

Основная последовательность:

`raw → captured → normalized → deduplicated → clustered → researched → understood → connected → validated → knowledge → canonical → evolving`

Дополнительные состояния:

- `disputed` — знание оспаривается;
- `superseded` — заменено более новым;
- `archived` — сохранено как история;
- `rejected` — отклонено;
- `draft`, `review`, `active` — временно сохранены для обратной совместимости старых объектов.

`canonical` не может возникать только из оценки, тега, кластера или автоматизации. Для канонизации действует процесс CKS: GAP → Evidence → Proposal → Decision → Minimal Change.

## 4. Связь с Obsidian

Корень Git-репозитория можно открыть как Obsidian Vault (хранилище Obsidian).

Рабочий модуль `tools/cks_knowledge_runtime.py` умеет создавать производные Markdown-файлы с:

- YAML frontmatter (метаданные);
- русскими человекочитаемыми подписями;
- `[[wikilinks]]` между объектами;
- тегами;
- кластерами;
- проектами-проекциями;
- ссылками на доказательства.

Подробности: `obsidian/README.md`.

## 5. Динамические представления

Рабочий контур формирует одновременно несколько проекций базы:

- по статусам;
- по типам;
- по кластерам;
- по тегам;
- по проектам;
- по уверенности;
- по стадиям «материал → знание».

Представление не копирует источник истины. Оно пересобирается из объектов.

# Часть II. CKS Knowledge Intelligence (аналитика знаний)

Рабочий модуль: `tools/cks_knowledge_intelligence.py`.

## 1. Поиск скрытых связей

Модуль сравнивает объекты по общим кластерам и тегам и выдаёт кандидаты связей с оценкой сходства и объяснением причины.

Результат имеет статус `suggestion_only` — только предложение.

## 2. Выявление новых кластеров

Объекты с устойчивым совпадением тегов собираются в предлагаемые группы `AUTO-CLUSTER-*`.

Автоматически найденный кластер не становится каноническим кластером без проверки.

## 3. Анализ «что стало знанием»

Модуль отслеживает историю состояний объекта и показывает, какие элементы дошли до `knowledge`, `canonical`, `evolving` и других зрелых состояний.

Для каждого такого объекта показываются:

- путь статусов;
- количество доказательств;
- количество связей;
- кластеры;
- факт прохождения ранних стадий.

## 4. Карта развития проекта

Проект рассматривается как выборка объектов из общего графа.

Карта показывает:

- состав объектов;
- распределение по стадиям;
- ключевые кластеры;
- временную историю переходов.

Это позволяет визуально видеть превращение входного материала в структурированное знание.

## 5. Самоаудит качества знаний

Диагностическая оценка использует:

- полноту метаданных;
- наличие доказательств;
- связность;
- классификацию кластерами и тегами;
- историю объекта.

Оценка качества является сигналом для проверки, а не истиной и не решением.

# Границы безопасности архитектуры

```text
динамическое представление ≠ SSOT
аналитическая оценка ≠ Decision
предложенная связь ≠ подтверждённая связь
предложенный кластер ≠ Canon
Obsidian graph ≠ источник истины
проект ≠ контейнер знаний
интуиция ≠ доказательство
```

## Русский язык

Человеческий слой CKS ведётся на русском. Английский сохраняется только там, где он нужен технической совместимости: код, имена API, поля JSON/YAML, GitHub Actions и другие машинные идентификаторы.
