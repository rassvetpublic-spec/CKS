# CKS Schema Field Audit v1

## Назначение

Документ фиксирует первый аудит полей YAML-схем CKS после переноса знаний из рабочего чата.

Цель:

- подтвердить существующие объекты;
- связать объекты со схемами;
- определить обязательные поля;
- выявить зоны дальнейшей проверки CKS v1.2.

---

# Проверенные основные схемы

## Решение (Decision Record)

Файл:

`schemas/decision_record_v1.yaml`

Назначение:

Хранение принятого решения.

Проверенные элементы:

- идентификатор решения;
- статус;
- варианты;
- выбранный вариант;
- обоснование;
- ссылки на доказательства.

Связи:

`Decision -> Evidence`

---

## Доказательство (Evidence Record)

Файл:

`schemas/evidence_record_v1.yaml`

Назначение:

Хранение основания решения.

Проверенные элементы:

- источник;
- тип источника;
- факт;
- уровень доверия;
- дата.

Связи:

`Evidence -> Decision`

---

## Пакет контекста (Context Package)

Файл:

`schemas/context_package_v1.yaml`

Назначение:

Перенос контекста между рабочими сессиями.

Проверенные элементы:

- источник;
- тип контекста;
- ссылка на материал;
- режим разделения.

Связи:

`Context -> Distillate`

---

## Договор артефакта (Artifact Contract)

Файл:

`schemas/artifact_contract_v1.yaml`

Назначение:

Описание результата и его требований.

Проверенные элементы:

- статус;
- источник;
- доказательства;
- ссылка решения;
- правила канона.

Связи:

`Artifact -> Decision -> Evidence`

---

## Объект выделенных знаний (Distillate Object)

Файл:

`schemas/distillate_object_v1.yaml`

Назначение:

Передача обработанного знания.

Проверенные элементы:

- версия;
- задача;
- идентификатор исполнителя;
- статус;
- данные знания.

Связи:

`Distillate -> Context`

---

# Найденные пробелы

1. Требуется полный аудит всех YAML-схем.
2. Требуется автоматическая проверка связности объектов.
3. Требуется фиксация версий схем в реестре.
4. Требуется проверка обратной совместимости при изменениях.
