# README Evolution Pattern — принцип развития сложности описания систем

## Назначение

Этот шаблон определяет, как документация проекта должна расти вместе со сложностью системы.

Главный принцип:

> Сначала объясняется смысл системы, затем структура, затем внутренние механизмы.

README не должен сразу становиться техническим справочником.

---

## Уровни развития описания

```
0. Название и назначение
        ↓
1. Простое объяснение
        ↓
2. Проблема и причина появления
        ↓
3. Верхнеуровневая архитектура
        ↓
4. Модель объектов
        ↓
5. Жизненный цикл
        ↓
6. Контроль и аудит
        ↓
7. Эволюция системы
```

---

## Уровень 0 — Идентичность

Цель: понять проект за несколько секунд.

Содержит:

- название;
- одно предложение о назначении;
- основную ценность.

---

## Уровень 1 — Объяснение простыми словами

Цель: дать понимание человеку без технического опыта.

Ответить:

- что это;
- зачем существует;
- какую пользу даёт.

---

## Уровень 2 — Проблема

Показать переход:

```
Было:
хаос, потеря информации, повторение ошибок

Стало:
структура, история, контроль
```

---

## Уровень 3 — Архитектура сверху

Показать:

- основные части;
- границы ответственности;
- направление движения данных.

Без глубоких деталей реализации.

---

## Уровень 4 — Модель объектов

Описать:

- какие сущности существуют;
- какие данные они хранят;
- как связаны между собой.

---

## Уровень 5 — Жизненный цикл

Показать путь объекта:

```
создание
 ↓
проверка
 ↓
изменение
 ↓
версия
 ↓
история
 ↓
архив или новый статус
```

---

## Уровень 6 — Контроль качества

Добавить:

- проверки;
- ограничения;
- аудит;
- доказательства.

Важно:

```
анализ ≠ решение
предложение ≠ канон
автоматизация ≠ утверждение
```

---

## Уровень 7 — Эволюция

Для зрелых систем описывать:

- развитие архитектуры;
- миграции;
- восстановление;
- самоаудит;
- новые возможности.

---

## Универсальная структура README

1. Что это простыми словами.
2. Какую проблему решает.
3. Основная идея.
4. Как устроено сверху.
5. Основные компоненты.
6. Как работает процесс.
7. Как система проверяет себя.
8. Как развивается.
9. Архитектурные принципы.
10. Техническая документация.

---

## Правило роста

Маленький проект:

```
уровни 0–3
```

Рабочий проект:

```
уровни 0–5
```

Большая система:

```
уровни 0–7
```

Платформа:

```
добавляются управление правилами,
аудит, жизненный цикл и эволюция
```
