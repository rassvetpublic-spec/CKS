# ADR-0001: Архитектура Дистилляции Знаний (Multi-Worker Distillate)

## Статус
**Принято** (Утверждено внешним QA-аудитом Codex)

## Контекст
В мульти-агентной среде под управлением KAT9I_OS (4 локальных воркера через прокси 8045 или распределенный рой) слепое копирование полных логов чатов приводит к:
1. Переполнению контекстного окна (Context Window Exhaustion).
2. Растрате токенов (Token Waste).
3. Потере фокуса (Коллизии рассуждений).
4. Угрозе утечки приватных данных между задачами.

## Решение
Мы внедряем **Паттерн Дистиллята (Distillate Pattern)** со строгим разделением Control Plane и Data Plane.

1. **Контракт Дистилляции:** Воркер в конце каждого ответа генерирует машиночитаемый JSON-объект (distillate_object_v1).
2. **Separation of Concerns (Отказ от прямого доступа):** Воркер не взаимодействует с базами данных (CKS). Инфраструктура (Прокси-менеджер KAT9I_OS) перехватывает JSON и укладывает его в буфер.
3. **Immutability (Неизменяемость):** 
   - *Raw Distillate* (Сырой лог) неизменяем и работает по принципу Event Sourcing.
   - *Approved Knowledge* (Подтвержденные знания в CKS) также неизменяемы, редактирование создает новую ревизию.
4. **Валидация (Anti-Poisoning):** Сырой дистиллят не попадает в канон напрямую. Фоновый процесс (TRIM) назначает QA/Validator Worker'а, который проверяет сырой факт и либо отклоняет его, либо промоутит в CKS.
5. **Приватность:** Для задач с грифом [SECURE] или [PRIVATE] поле data_plane отсекается. В базу уходит только телеметрия.

## Последствия (Consequences)
- **Позитивные:** Экономия токенов, устранение File-Lock коллизий (локальный кэш через SQLite WAL), защита от отравления базы галлюцинациями LLM.
- **Негативные/Риски:** Требуется разработка фонового планировщика (TRIM/GC) и выделение ресурсов под QA Validator'а.
