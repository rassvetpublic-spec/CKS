# ADR-0002: Знание-центричная модель рабочего контура CKS

## Статус

Принято.

## Контекст

CKS уже содержит рабочий граф знаний, движок происхождения знаний, непрерывные проверки управления и систему самопроверки. Следующий разрыв состоит в том, что единица работы всё ещё недостаточно богато описывает развитие знания, кластеры, теги, интуитивные сигналы, разные представления и совместимость с Obsidian.

## Решение

Развитие CKS ведётся вокруг двух связанных слоёв:

1. Knowledge Runtime (рабочий контур знаний) — единая модель объекта знания, кластеры, теги, жизненный цикл, динамические представления и совместимое Markdown-представление для Obsidian.
2. Knowledge Intelligence (аналитика знаний) — поиск скрытых связей, предложения новых кластеров, анализ превращения материала в знание, карта развития проекта и самоаудит качества знаний.

Проект не является контейнером файлов. Проект — одна из проекций графа знаний.

## Граница решения

- CKS v1.2 Core (ядро) остаётся замороженным.
- Новые компоненты относятся к развиваемому рабочему слою и не переписывают Core автоматически.
- Производный граф, представления, метрики и аналитические предложения не являются SSOT (единым источником истины).
- Аналитика не принимает Decision (решение) и не меняет Canon (канон) автоматически.
- Русский язык является основным человеческим языком документации и пользовательских представлений; технические идентификаторы сохраняются на английском языке согласно ADR-007.

## Принятый жизненный цикл знания

`raw → captured → normalized → deduplicated → clustered → researched → understood → connected → validated → knowledge → canonical → evolving → disputed → superseded → archived → rejected`

Переход к `canonical` допускается только через действующий процесс GAP → Evidence → Proposal → Decision → Minimal Change.

## Obsidian

Корень Git-репозитория CKS может открываться как Obsidian Vault (хранилище Obsidian). Markdown-представления являются производным визуальным слоем и не заменяют исходные объекты CKS.

## Последствия

- схема объекта знания расширяется без разрушения старых технических идентификаторов;
- добавляется рабочий модуль Knowledge Runtime;
- добавляется модуль Knowledge Intelligence;
- создаётся совместимый шаблон Obsidian;
- самопроверка CKS контролирует новый рабочий слой.
