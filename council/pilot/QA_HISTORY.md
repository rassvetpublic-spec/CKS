# QA-история — извлечённый срез

Статус документа: историческое резюме, не новое одобрение. Источники: SOURCES.md.

## KU-001 Decision

S1 предлагает проверить, можно ли сохранить обоснованное решение о разделении
CKS и KAT9I_OS с контекстом, вариантами, последствиями и основаниями.
S2 сообщает PASS и VALIDATED FOR PILOT. Замечания F-063/F-064 утверждают
достаточность текущей модели; F-065 удерживает роли и владельцев вне CORE.
Пересказ не подтверждает существование отдельного принятого объекта в Git.

## KU-003 Rule

S3 сообщает PASS правила «CKS не является Runtime».
F-066/F-067 описывают правило как знание, а не механизм исполнения.
F-068 требует происхождение Rule → Decision через существующую связь.
Следующим назван KU-002 Idea; рекомендация QA не является решением владельца.

## Сверка с репозиторием

- Архитектурная граница в S1–S3 совпадает с S4.
- STABLE из бесед расходится с Release Candidate в S5.
- Заявленные KU-файлы не обнаружены в исходном Git SHA.
- Отсутствуют привязка этих PASS к PR_HEAD и проверяемое решение владельца.

Вывод: историю можно использовать как материал для кандидата решения.
Автоматически переносить чатовые PASS в accepted/canon нельзя.
