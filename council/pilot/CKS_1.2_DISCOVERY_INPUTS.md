# CKS 1.2 Discovery Inputs

## Source

Derived from CKS 1.1 production tests.

## Inputs

1. Graveyard / rejected history gap

Need:
- preserve rejected proposals
- preserve rejection reasons
- preserve evidence
- prevent automatic resurrection

2. Council lifecycle

Need:
- separate proposal, review, decision and acceptance states

3. Decision Memory

Need:
- remember why alternatives were rejected
- keep historical context without promoting it to canon

## Constraints

- No CORE modification.
- No automatic acceptance.
- No runtime state in knowledge objects.
