# CKS 1.2 — сверка двух экспортов

Статус: `NEEDS_REVISION` для репозиторного принятия. Это сверка свидетельств,
а не Human Gate и не независимый QA.

## Совпало в A и B

- CKS 1.1 считается стабильным в обеих беседах.
- CORE считается замороженным.
- CKS хранит знания; исполнение относится к KAT9I_OS.
- Context Passport, Worker Manifest, Adapter, Import Pipeline, Advanced Validation
  и Promotion Workflow обсуждались как будущие направления.
- CKS 1.2 не следует реализовывать без реальной подтверждённой проблемы.
- Авторы чатов не нашли оснований добавлять runtime, память агентов или новые поля CORE.

Классификация: `CONFIRMED_IN_BOTH_CHATS`; всё ещё требуется GitHub-проверка.

## Различия

1. Экспорт A перечисляет «неизвестные» файлы и ADR как упомянутые.
   Экспорт B называет ADR-001…ADR-007 и дополнительные документы.
   Классификация: `GITHUB_VERIFICATION_REQUIRED`.
2. Экспорт A оставляет CKS 1.2 как `PROPOSAL`; B формулирует «Discovery only».
   Это совместимо по смыслу, но требует одного канонического решения.
3. B выделяет правило Lifecycle ≠ Workflow и риск поиска знаний; A формулирует
   близкие риски через документацию и границы Adapter. Нового противоречия нет.

## Что нельзя принять автоматически

- чатовый PASS не подтверждает PR, commit, файл или Evidence;
- STABLE из чата расходится с Release Candidate в `docs/CKS_CURRENT_STATE_REPORT.md`
  проверенной версии Git;
- KU-001…KU-005 и перечисленные ADR не найдены в исходном SHA;
- ни один экспорт не является решением владельца.

## Рекомендация

Считать согласованным только ограничение: `CKS 1.2 = Discovery only`.
Оставить кандидат решения draft. Следующий шаг — проверить упомянутые артефакты
в ветке `council-v0.1`, затем отдельно решить, создавать ли эксплуатационные объекты.
